# V11: TPM bring-up inside the BIOS (no shim chain)

> **Status: built and verified offline. Not yet tested on hardware.** Do the dry run (step 1) before you flash.

V9 + tpmboot works (Battlefield 6 runs), but it relies on a chain outside the firmware: Microsoft-signed shim, then a MokManager hash, then tpmboot, then Windows. V11 moves tpmboot's job into the BIOS as a DXE driver, **TpmBootDxe** (`tpmdxe/tpmdxe.c`). On every boot, once the firmware's ACPI table protocol is up, it:

1. opens the LPC decode window for `0xFED40000`, if firmware TPM support is off,
2. sends `TPM2_Startup(CLEAR)` + `SelfTest`,
3. installs the TPM2 ACPI table,
4. re-checks the LPC window just before the OS loader starts.

| | V9 + tpmboot | V11 |
|---|---|---|
| Boot path | firmware → shim → tpmboot → bootmgfw | firmware → bootmgfw (stock) |
| Secure Boot | Microsoft keys + MOK hash enrollment | Microsoft keys only. Code in flash isn't checked by Secure Boot |
| Microsoft revoking shim (SBAT/DBX update) or the 2011 CA | Chain stops getting the TPM table | Not affected |
| Windows reinstall / ESP wiped | Run `install_sb.nsh` again | Not affected |
| CMOS clear | Boot order and setup variables need fixing | Nothing to do (firmware TPM support defaults to off) |
| Rebuilding the TPM code | Enroll the new hash in MokManager | Reflash |

Both versions have the same limits. The firmware writes no TCG event log (measured-boot attestation sees empty PCRs), and the clear-TPM button in Windows doesn't work. To clear the TPM, use `tpmclear.nsh` or `tpmboot.efi` with the clear flag from the stick.

## Build

```bash
bash tpmdxe/build.sh                                   # tpmdxe.efi, sha256 0aafe843...
python3 firmware/build_tpm2_bios.py --stock Z97MOCF2.50 --donor Z97Ex62.80A \
        --tpmdxe tpmdxe/tpmdxe.efi --out Z97MOCF_TPM2_V11_8MB.bin       # sha256 ff3fcc89...
python3 firmware/verify_image.py Z97MOCF_TPM2_V11_8MB.bin --stock Z97MOCF2.50
bash usb/make_usb.sh                                   # stick now also has tpmdxe.efi + test_tpmdxe.nsh
```

V11 is V9 plus one extra FFS file in the DXE volume: GUID `78c18031-b5ae-4112-a635-70285b920a2f`, type DRIVER, sections DXE_DEPEX (`PUSH EFI_ACPI_TABLE_PROTOCOL, END`), PE32 and UI "TpmBootDxe". Everything else is byte-identical to V9.

## Migrate from V9 + tpmboot

**1. Dry run, without flashing (recommended).** This runs the exact same driver binary from the stick.
- BIOS: Secure Boot **Disabled** for this test only.
- Boot the stick (F11), then run `test_tpmdxe.nsh`. It loads `tpmdxe.efi` as a driver and starts Windows straight from the shell.
- In Windows, `tpm.msc` should show ready, 2.0. If it does, the driver does its job on your board.
- Reboot, set Secure Boot back to **Enabled**, and you're back on your working V9 setup.

**2. Back up the chip.** Read it **twice** and compare. This dump is your rollback: V9 plus your NVRAM, which holds the Secure Boot keys, setup settings, MAC and serial.

**3. Remove the shim chain** (admin PowerShell, in Windows):
```powershell
powershell -ExecutionPolicy Bypass -File migrate\remove_shim_chain.ps1
```
The script suspends BitLocker if it's on. It restores `\EFI\BOOT\BOOTX64.EFI`, deletes `\EFI\tpmboot`, deletes the "TPM Boot" firmware entries, and puts Windows Boot Manager first. Until V11 is flashed, Windows won't see the TPM.

**4. Flash V11 with your own NVRAM**, so Secure Boot keys and settings are kept:
```bash
python3 firmware/merge_nvram.py --dump my_v9_dump.bin --mod Z97MOCF_TPM2_V11_8MB.bin --out flash_v11.bin
```
Flash `flash_v11.bin` and verify.

**5. Check:** `tpm.msc` shows ready, 2.0, and `msinfo32` shows Secure Boot **On**. Then launch BF6.
Also test **sleep → wake → `tpm.msc`**. It has the same S3 caveat as V9: the firmware doesn't restore the TPM after S3 resume. If the TPM disappears after waking, use shutdown/hibernate instead of sleep and tell us.

Setup variables: firmware TPM support **off** (`tpm_fw_off.nsh`) is the intended setting, and it is also the board default after a CMOS clear. Only if `tpm.msc` shows no TPM in that mode, try `tpm_fw_on.nsh`.

## Rollback

Flash your step-2 dump. Then, from the stick, run `install_sb.nsh` again to restore the shim chain. MokManager still remembers the old tpmboot hash, so no new enrollment is needed.

## Failure modes, and why V11 can't block boot

- If no TPM is attached, DID_VID reads FF both before and after opening the LPC window, and the driver returns at once.
- If the TPM doesn't answer, every wait has a timeout: locality 200 ms, cmdReady 500 ms, per-byte burst 200 ms, response 3 s. If Startup fails, the driver doesn't install the TPM2 table, so Windows sees no TPM rather than a broken one.
- The driver only depends on `EFI_ACPI_TABLE_PROTOCOL`. If that protocol is somehow missing, the driver is never dispatched and the board boots like V9 without tpmboot.
